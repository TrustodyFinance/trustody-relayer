# Trustody Relayer

The official binary distribution repository for Trustody Relayer. It advances wallet requests that satisfy their approval and release conditions, submits transactions to supported networks, and helps track their results.

The relayer's identity is an execution credential, **not an asset private key**. It cannot approve payments or change an approved recipient or amount. Self-hosting reduces dependence on the platform's relayer service; it does not remove the platform's authority to upgrade wallet programs.

## Installation and setup

Prefer the pinned installation command generated by your wallet under **Settings → Relayer → Register a self-hosted relayer**. The command verifies the installer fingerprint, and the installer verifies the binary. It carries your wallet number (`sh install.sh <wallet-number> [--platform <id>]`); on a machine where the relayer is already installed, the same command only adds that wallet. Networks come from the wallet's catalog and use its default public nodes until you add your own with `trustody-relayer rpc add <network> --provider <name> --key <key>` or `--url <URL>`; RPC addresses and keys stay in `rpc.toml` on the relayer machine.

Linux / macOS:

```sh
curl -fL 'https://github.com/TrustodyFinance/trustody-relayer/releases/download/relayer-v0.2.0/install.sh' -o install.sh
actual=$( (sha256sum install.sh 2>/dev/null || shasum -a 256 install.sh) | cut -d' ' -f1)
[ "$actual" = '05d4c4e63fd8defc18e6a4a9dfbb8e9148f1626ffc1d53c5261ade904638660a' ] && sh install.sh
```

Windows (PowerShell):

```powershell
Invoke-WebRequest -UseBasicParsing 'https://github.com/TrustodyFinance/trustody-relayer/releases/download/relayer-v0.2.0/install.ps1' -OutFile install.ps1
if ((Get-FileHash ./install.ps1 -Algorithm SHA256).Hash.ToLower() -ne '8fd0652cdb15809f3a1b6233cbcba8013d68075487201115826b850b858dc5d1') { throw 'checksum mismatch' }
powershell -NoProfile -ExecutionPolicy Bypass -File ./install.ps1
```

Setup creates configuration and a private identity file, then displays the public relayer ID. Register that ID in the wallet (an operations request) and route networks to it. Submission alone does not activate the registration. Never paste the PEM identity contents into the wallet or publish them in logs or issues.

## Operation

These commands assume the binary is installed and `config.toml` is the intended configuration. Use the installed configuration's actual path. For a Linux system installation, run configuration and identity operations as its dedicated service account, with an explicit configuration path.

```sh
trustody-relayer --version
trustody-relayer --help
trustody-relayer status --config ./config.toml
trustody-relayer check --config ./config.toml --lang en
trustody-relayer run --config ./config.toml
```

`status` reports identity, wallet acceptance and service state; a successful command alone does not establish health. `check` diagnoses configuration, permissions, connectivity and wallet access. `run` stays in the foreground and stops when the terminal closes. Run **one instance per identity**, including across hosts; do not start a foreground copy alongside a service. Arrange continuous operation with your host's service manager or container platform.

Protect and retain configuration, RPC and identity material across restarts, updates and redeployments. Keep the lock path writable by the running account. File permissions must restrict private material to its owner. `add-wallet`, `remove-wallet` and `rpc` changes take effect at the next cycle; after other changes with `set`, check and restart.

## Containers and secrets

```text
ghcr.io/trustodyfinance/trustody-relayer@sha256:859535db7f2e1d792c6aba31f1f9233119337212cd9ca67f08fb2e0cd1284cbd
```

Supply configuration through a private file or `TRUSTODY_RELAYER_CONFIG_TOML`, and RPC nodes through `TRUSTODY_RELAYER_RPC_TOML`. For the identity, choose **either** the configuration field `identity_pem` **or** `TRUSTODY_RELAYER_IDENTITY_PEM`; supplying both is rejected. Local file paths are not automatically available inside a container.

For an environment-based cloud configuration, set `lock_file` to a writable path such as `/tmp/trustody-relayer.lock`. Persist the identity secret separately from temporary container storage. A container does not upgrade itself and cannot run `rpc` or `rotate`: change the secrets and redeploy. Secret administrators can read execution credentials and RPC keys, so limit access.

## Rotation, updates and removal

`trustody-relayer rotate --config ./config.toml` creates a new identity and asks every wallet in the local list, with the old identity, to replace it (`relayer_rotate`); nothing is pasted in the wallet. The old identity file is deleted once every wallet has confirmed; an unreachable wallet keeps the old identity until a later `rotate` (or the running service) completes it. In a cloud deployment, register a new relayer in the wallet instead and remove the old registration.

Updates are automatic by default: at start and every 6 hours the relayer installs a newer release only if its Sigstore signature identity is exactly the release workflow on that `relayer-vX.Y.Z` tag **and** the platform's multi-signature `SetRelayerVersion` approved it (never a revoked or older version), after the new program passes `--self-check`. Install with `--no-auto-upgrade` to update manually. Before uninstalling or deleting a deployment, arrange a replacement relayer or complete the wallet's switch back to its platform relayer. Retain identity and configuration material until the replacement works; uninstalling the program does not change wallet authorization.

For wallet concepts and detailed procedures, use the guide provided in your Trustody wallet. When reporting a distribution issue here, include the release version and a redacted error; never include configuration secrets or identity files.
